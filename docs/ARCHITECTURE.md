# Supraman architecture

For whoever is about to change Supraman, or to build another gpui tool (GitMan, FileMan) on its crates. What was
measured and why is in `docs/LEARNINGS.md`; what comes next is `docs/ROADMAP.md`; the keys are `docs/KEYS.md`.

**Boundaries.**
- Only `supraman-claude` runs `claude` outside a terminal tab or parses its output; a tab runs `claude` in its PTY (`hand.rs`, `view.rs` `attach`).
- Only `supraman-workman` talks HTTP to Workman (`supraman-supervisor`'s `mint.rs` uses its `http_agent`). Nothing in Supraman writes Workman items; the MCP tools are the agents' write path (C21).
- `supraman-supervisor` never polls and never paints: the app's upkeep and `sm` call it.
- `supraman-core` and `supraman-term` have no Supraman crate dependencies; `supraman-ui` has no `claude` or Workman knowledge.
- The OS boundary is `supraman_core::platform::{process, open, locale, fs, paths, desktop, shell, secret, tasks}`: each module the Windows code of one concern, and off Windows a stub that refuses with `platform::NOT_HERE`'s words. No `windows::` call sits outside it but the vendored `supraman-term`, the selftests' `selftest/win.rs` and a test's setup of an OS condition (refactor4/17).
- `supraman-app`'s default feature `selftest` builds the `--selftest*` modes (`selftest.rs`, `selftest_*.rs`, `selftest/`), their Win32 harness (the `windows` crate) and GitMan's `test-support` for 7g's fixture repo. Without it the app builds no selftest; `selftest_seams.rs` holds the hooks the app's own code keeps either way.
- `supraman-git-view` knows no session, group or tab: the app hands each `GitView` its `occupancy::Live` and places it in a tab.
- `supraman-work-view` knows no tab, sidebar or session launch: the app hands each `WorkView` its `Opening` (its `Target`, folders, `FleetLink` to the live sessions and attach, `open_link_with`, `repo_of`) and places it and the Inbox's cards.
- `plugins/supraman` is not a crate: the Claude Code plugin loaded with `--plugin-dir` on sessions Supraman launches — `plugins/supraman/hooks/hooks.json` (exec-form `sm.exe hook <event>`), `plugins/supraman/roles/hand.md`, and the skill `supraman-scheduler`. See `plugins/supraman/README.md`.
- `spikes/term-spike` is not product: the m0/5 terminal spike, kept building against `supraman-term` and `supraman-ui`. Nothing depends on it.
- `probes/` holds the m0 measurement scripts; `scripts/` holds `scripts/release.ps1`, `scripts/shot.ps1` and `scripts/icon-gen/`.

## Shared components and helpers

Use these; do not grow a private copy (CLAUDE.md, C56). If none fits, extract one into the crate it belongs to and add it here and to CLAUDE.md.

### supraman-core (`crates/supraman-core/src/`)

- `fs::write_atomic` — every write of a file another process or thread may read (settings, registry, minted sessions). A unique temp file renamed over the target.
- `fs::lock_file` — an exclusive cross-process lock held while the returned file lives, around a read-modify-write (`folders::edit`, `schedule::edit`, `refresh.lock`). `fs::try_lock_file` takes it only when free (`None` while held): a schedule's overlap lock.
- `fs::load_json_or_notice` — a JSON state file whose loss is a notice, not an error (stars, dismissals).
- `store::{JsonStore, Save}` — a small JSON state file held in memory, each in its own format (`starred.json`, the schedules' dismissed runs and approvals, `workstate-dismissed.json`): `load` reads it with `load_json_or_notice`, `edit` changes the value and returns the `Save` of a change, `Save::write` writes the newest value with `write_atomic` (a save overtaken by a later one writes nothing); the app runs it with `supraman_ui::store::save_off_thread`.
- `fs::append_capped` (with `fs::rotated`) — an append-only log rotated to `<file>.1` at a cap (event logs, `supraman.log`).
- `paths::{user_home, claude_dir}` — the user's home and claude's config dir (`CLAUDE_CONFIG_DIR`-aware); never read `USERPROFILE`/`HOME` yourself.
- `paths::{normalize, path_key, within, key_within, git_at, main_checkout, linked_git_dir}` — path comparison (`within`: a folder or below it, never a sibling sharing a prefix) and the `.git` file/dir walk without running git; `git_at` is the nearest `.git` (a repo's folder or a linked worktree's file) at or above a folder, the walk `branch_at`, `main_checkout` and the Details tab's worktree line share.
- `time::{now_ms, epoch_ms, modified_ms, hex6}` — epoch milliseconds and a scratch-name suffix.
- `time::{local, ago, clock, short, near, date_words, rfc3339_local, rfc3339_in, stamp, stamp_in, Locale, user_locale}` — the times the UI shows, in this computer's zone: `ago` (rows, notices, Details), `clock` (the update line), `short` (a tab's hover card), `near` (next and last fires), `date_words` (Details, Approve), `rfc3339_local` (the Work tab's server times), `stamp` (the Git tab's dates: the user's short date and short time from `GetLocaleInfoEx`, read once).
- `hex::{encode, decode}` — bytes as lowercase hex, two digits each, and back; every digest, key file name and MAC written as hex.
- `update::{Manifest, sign, verify, release_keys, sha256_file, signature_path}` — a release's `supraman-update.json` (its bytes as written are what is signed), its ed25519 signature file and the release keys compiled in from `update.pub`; `Manifest::check_zip` checks a downloaded zip. `sm release` writes and signs it; the app's update check and install use it.
- `prune::{prune, KEEP_MS}` — the one retention rule for what sessions leave in the home: event logs, the Start page's prompt files, and the schedules' rotated run records and spent run worktrees, after 30 days unmodified, and the state dirs of removed schedules. The app's upkeep runs it hourly.
- `url::origin` — the one origin rule; origins key `servers.json` and the minted records.
- `process::{command, run, run_watched, run_bytes, stream, git, alive, spawn_detached}` — every child process outside the PTY: no console window, both pipes drained, a timeout that kills the child or its tree (`Kill::Child` for `claude`, whose tree holds the background service), pid liveness. `run_watched` also kills the child when its `stop` returns true and returns what a killed child wrote (`Ended::{Exited, TimedOut, Stopped}`). Never `Command::new(..).output()` by hand.
- `platform::{process, open, locale, fs, paths, desktop, shell, secret, tasks}` — the OS boundary (Boundaries above; CLAUDE.md lists each module's items): `process` (`started`, `terminate_started`, `wait_any_exit`, `snapshot`, the one Toolhelp32 walk, `memory`, `is_elevated`, `pid_elevated`), `open` (`open`, `runas`), `locale::user`, `fs` (`exe_name`, `EXE_SUFFIX`, `hidden`, `is_reparse_point`, `is_app_alias`, an install's renames), `paths` (`data_dir`, `user_profile`), `desktop` (the hidden desktop, the single instance, windows by HWND, the tray's icon size, `detach_console`, `windows_build`), `shell` (`PowerShell`, `terminal_powershell`, `pathext`, `expand_env`, `git_roots`, `in_git_bash`, `detect`, `script_command`, `launch`), `secret` (`seal`, `unseal`, `restrict_to_owner`), `tasks` (`WindowsRegistrar`).
- `home::{home_from_env, default_home_from_env, env_home, home_env, SessionEnv}` — the Supraman home (`SUPRAMAN_HOME`, else `%APPDATA%\Supraman`; `default_home_from_env` that default alone) and `SessionEnv`, the one writer (`vars`) and reader (`from_env`) of a session's `SUPRAMAN_ROLE`, `SUPRAMAN_SESSION` and `SUPRAMAN_REPO`.
- `testing::{eventually, wait_until, polled}` (feature `test-support`) — every test's wait for what another thread or process does; never a deadline loop of a test's own.
- `secret::{SecretStore, FileStore, MemoryStore, default_store}` — every secret at rest: one DPAPI-encrypted file per key under `<home>/oauth/secrets`; `MemoryStore` in tests.
- `slug::{slugify, validate_name, FM_PREFIX}` — a folder or group name as a session-name part (a [+] session's `hand-<slug>` too); every Supraman session name starts with `fm-`.
- `slug::{name_char, is_session_name, is_safe_id}` — the other name rules: a typed character of a `validate_name` name (a group's name), a session name safe as a file-name part (`mcp_config_path`), a session id as a file name (`events`).
- `Settings::update` — every change to `settings.toml`: load, edit, save under `<home>/settings.lock`. `Settings::load_with_notices` when a bad key should be shown.
- `Settings` sections (`sessions`, `appearance`, `terminal`, `window`, `updates`, each a `Section`; a former `[workman]` or `[workstate]` table is kept as another owner's, never read) — a key belongs in its table; another owner's table (a plugin's `[gitman]`) goes through `Settings::section`/`set_section` and survives every save.
- `folders` (`load`, `edit`, `Entries`, `Entry`, `FolderEntry`, `Place`, `Pos`, `on_disk`, `subfolders`, `shown`, `Shown`, `SKIPPED`) — `<home>/folders.toml`, the sidebar's ordered entries: a folder (`show_subfolders`: its direct child folders shown as rows, `subfolders`' rule: folders only, by name, no dot, hidden or `SKIPPED` build folder), or a group (a unique `validate_name` name) of folders; read and written only here, edits under `folders.lock` with `write_atomic`, a file that does not parse an error and kept; created once from the workspace files (each workspace a group of its folders, a path kept at its first place, homes dropped).
- `folders::migrate` — the one reader of an earlier release's `<home>/workspaces/<name>.toml`: folders.toml's first entries and the folder names `schedule::migrate` places the earlier per-workspace schedules by; compat code removed in 0.1.19 (backlog/end-controllers-removal).
- `branch_at` — the branch checked out at a folder by its nearest `.git`, no git run.
- `folders::Entries` edits (`folders/edits.rs`) — add a folder at a `Place` (the top level or a group, at an index; refused where that list holds it), remove or move one by `Pos`, add, rename or remove a group (its folders to the top level where it was, or with it); shared by `sm folder`/`sm group` and the app's Add Folder.
- `schedule` (`schedule/`: `load`, `edit`, `approve`, `covered`, `verify_approval`, `effective_status`, `next_fire`, `previous_fire`, `next_fire_local`, `append_run`, `read_runs`, `runs`, `run_worktrees`, `command_file`, `base_prompt`, `preamble`, `run_stamp`, `run_id`, `session_name`, `run_worktree`, `DEFAULT_DENY`, `Profile::permission_mode`, `Permissions::{allowed, denied}`) — the scheduler's model (`docs/research/scheduler.md`): one TOML per folder at `<home>/schedules/<key>.toml`, `key` the folder's `folder_key` (its name's slug and 8 hex of the sha256 of its `path_key`; one function owns it), the file holding the folder's path; changed only through `edit` under `<key>.lock` + `write_atomic`. Everything else of a schedule is keyed by it too: run records `runs/<key>.jsonl`, `live/<key>/`, `state/<key>/<id>/`, secrets `supraman/schedule/<key>/<id>/<NAME>`, the task folder and the run's session name `fm-<key>-sched-<id>-<stamp>`. `migrate` moves an earlier release's `schedules/<workspace>.toml` once (its schedules to their folders' files by the workspace's folder names, pending, with their records, live and state files and secrets; one with no folder kept under `schedules/unplaced/`, which `load_all` names) and leaves `RESYNC` for the app's next sync. `edit` keeps `[schedule.approval]` as it was, sets `pending` and clears `action.worktree` when a covered field changes, and keeps `active` only while the approval's fingerprint is the current one. The fingerprint is the sha256 of the canonical covered JSON (`v: 2`, the folder's path, the id, trigger, action with a slash command's name and path, permissions, caps, policy, and the script's and prompt file's sha256); the approval's MAC is HMAC-SHA256 of the folder's `path_key`, the id and the fingerprint under `APPROVAL_KEY` in the `SecretStore`, created on the first `approve`. `approve` is called only from the window's Approve (C100). Next fires take the zone as a parameter: a wall time a DST change skips fires at the first minute after the gap, a repeated one fires once. Run records go through `append_capped` (1 MiB); `prune` removes the rotated ones, the state of removed schedules, and run worktrees with nothing uncommitted and no commit of their own. `SCHED_SLUG_PREFIX` marks a run's session name; `schedule_of_session` is its one parser (folder key and id). A run works in its folder's checkout; only a schedule an earlier release saved with `worktree = true` gets a run worktree (`run_worktree`, `run_branch`), and only there may an `edit` run push its branch (`Permissions::allowed(always, run_branch)`). `Profile::Edit` reads `edit` and `worktree-edit` and fingerprints as `worktree-edit`, so earlier approvals verify. A run's names, its preamble (which says where the run works) and base prompt (a missing slash command or prompt file is `NoPrompt`, naming the folder), and a profile's `--permission-mode`, `--allowedTools` and `--disallowedTools` live here, so `sm schedule dry-run`, fire and the app agree; `sm`'s `schedule::run_spec` turns them into the run's `LaunchSpec`. `sync(&dyn Registrar, &SyncTarget, folder, &[Schedule])` registers one Windows task per schedule that is `active` with a verifying approval, at `<task_root(home)>\<key>\<id>` (`\Supraman` for `%APPDATA%\Supraman`, `\Supraman-<hex8 of sha256(path_key(home))>` for any other home), removes the rest of that folder and deletes it, then the root, when empty; it reads and writes nothing outside the folder. `sync_all` syncs every folder's file and `prune_tasks` deletes the root's task folders no key names (a removed folder's, the earlier workspaces'), never outside the root. `task_xml` builds the definition (InteractiveToken, the run level, StartWhenAvailable for `catch_up = once`, WakeToRun, `smw.exe schedule fire --home … <key> <id> --fingerprint …`); its `<Version>` is `definition_digest`, everything but the start date, so an unchanged task is left alone and a changed one (run level included) is registered again. `WindowsRegistrar` is COM `ITaskService`, each call on its own MTA thread; `FakeRegistrar` keeps the XML per path for tests and selftests (C101). The app is the only caller (C100). `covered_fields`/`covered_diff` flatten a covered JSON to sorted `field: value` leaves and diff two, which the window's Approve shows; `schedule_of_session` parses a run session's name back to its folder key and schedule id.
- `watch::{Watcher, Watch, Batch, Stopped}` — the one file watcher, on Zed's fork of `notify` (the one in the tree, through `[patch.crates-io]`): ReadDirectoryChangesW on Windows, no polling. The OS watcher lives on the `Watcher`'s own thread, which gathers changes into a `Batch` (each path once, sorted; `rescan` when the OS lost some) closed a debounce after its first change and handed to the owner's callback there. Dropping the `Watcher` sends a stop and returns at once; the thread drops the OS watcher and ends when notify's thread has let go of the handler, its handles closed, which `Stopped` reports (`tests/watch_drop.rs` counts the process's threads and handles).
- `events` (`append_event`, `EventReader`, `role_injection`) — the hook events `sm hook` appends per session.
- `install::{exe_dir, sm_exe}` — the running exe's folder, where `supraman.exe`, `sm.exe` and `smw.exe` ship side by side, and the `sm.exe` in it; `schedule::smw_exe` and every app and `sm` lookup of either goes through them.
- `install_hook_exe`, `hook_exe`, `find_plugin_dir`, `sm_allowed_tools` — placing `sm.exe` in the plugin, and the `--allowedTools` rules that keep `sm` and the `agents` server's launch, list and stop from parking (every [+] session and every scheduled run).

### supraman-ui (`crates/supraman-ui/src/`)

- `text_input` (`TextInput`, `LineText`, `bind_keys`) — the one text input, single- or multi-line, on gpui's `EntityInputHandler`: selection, IME, dead keys, clipboard. Every text field uses it.
- `hit::{HitTargets, hit_target}` — every clickable element records its painted bounds under its key; the selftests click through these.
- `button::{action, Tone, Fill, look, pill, icon, revealed, toolbar, toolbar_turning, ghost, choice, checkbox, tick, dimmed}` — every clickable button and tick box (`action`: every labelled button, a `Tone` (Neutral, Success, Danger) in a `Fill` (Solid, Outline); `checkbox`: a fixed 14 px square under its key, ticked in the accent colour, one size either way, on the letters of the label the caller adds (`ink::mark`), the caller adds the label and the click; `pill`'s label letters centred in it; `tick`: the same square as a read-only mark, a criterion's in the work view); the key is its element id, hover group and hit key; `toolbar_turning` turns its icon while work it started runs; `revealed` is a row's hover icon in a fixed slot: always laid out and painted, so nothing shifts and its hit key exists, shown while the row's group is hovered or the row is selected.
- `banner::{tinted, plain, dismissable, tint}` — every notice box: a status colour on its 0.12 tint.
- `fonts::{UI, MONO, icons, figures}` — the UI's font families; never spell a family name in a view; `figures` sets the UI font with tabular figures (dates, shas). The terminal's font is the user's (`Settings`).
- `menu::{ContextMenu, MenuItem, item}` — every right-click menu, generic over the owner's action type; items paint under `menu-<key>`; `MenuItem::under` starts a captioned section.
- `confirm::Confirm` — a question before an action that cannot be taken back (`ask`), or a report with only its OK (`report`); the owner places it.
- `toast::ToastSlot` — short feedback floating over a panel that goes by itself (`TOAST_FOR`); `show` marks a done action with ✓, `show_why` says why nothing was done.
- `notices::{NoticeKind, render, keep_dismissed, remove_one}` — a list of plain notices with a × each; the owner keeps the kinds and sources.
- `tabs::{tab_strip, TabHeader, DraggedTab, DraggedSession, reorder, cycled, sanitize}` — the tab strip with drag-to-reorder (`on_move(from, to)`; `DraggedTab { id }` is the payload any other drop target takes, `DraggedSession { session_id }` a session row's; a terminal pane takes both and pastes the session's SendMessage name), tab cycling, and a program's OSC title as a tab label; tab state and order stay with the owner.
- `hover_card::{HoverCard, tooltip}` — a hover card of a title and `label  value` rows.
- `icon::Icon` — Zed's Lucide icons (`assets/icons`, ISC, `THIRD_PARTY.md`) compiled in and tinted with a colour; `slotted` sizes one for a square slot so outlines and filled marks look one size.
- `tooltip::{Tooltip, LAST_SHOWN}` — a plain text tooltip; `LAST_SHOWN` is the text last shown, for the selftests.
- `clipped::{clipped, clipped_with, cut_at}` — a one-line label cut with an ellipsis (at the end or the middle) that carries its whole text as a tooltip while it is cut; `cut_at` is where a cut label was painted.
- `folder_picker::pick_folder` — the system folder picker; the owner gets the chosen folder after the window is activated again, so keys reach it whatever Windows gave the activation to.
- `split::SplitPane` — a resizable side-by-side split; the owner keeps and persists the width, the first panel's (`render`) or the second's (`render_second`). Its divider handle (`split::handle`, `DraggedDivider`) is also the table header's. `split::HeightBar` is a box over a short rounded bar that drags its height (min, max, double-click to the default), the owner keeping the height; its bar and the divider handle are one grab (`grip`), the same drag payload and end and reset calls.
- `table::{Table, TableState, Column, fit, drag, NearEnd}` — a table of columns over fixed-height rows on `gpui::uniform_list`, which lays out only the rows in view and measures one row, so a row count of tens of thousands, and pages appended to it, cost nothing per row (`KeyedList`'s `gpui::list` keeps a height per row and an anchor key, which variable rows need and these do not). The owner keeps each column's preferred width (where the user last dragged it) and persists the ones `on_resize(preferred)` reports when a divider is let go or double-clicked; `TableState` keeps the current widths. `table/widths.rs` is the rule, GitKraken's: the widths always sum to the table's (until every column is at its min); `drag` moves the dragged column and refits only those right of it (growing takes from the rightmost down to their mins, shrinking gives to columns below their preferred width, left to right, the rest to the last); `fit` does the same for a narrower or wider table; `clamp` holds saved widths within min and max (the last column has no max). A column at or below its icon threshold shows its icon, the caption as tooltip (hit key `<id>-col-<column>-icon`). `TableState` keeps the selection (click, Up/Down, `reveal`), the scroll (`scroll_top`, `set_scroll_top`) and the focus; `on_near_end` is called, deferred, once per approach to the last row and again when rows arrive (`NearEnd`). Header, dividers, hover and selection take theme tokens; the owner gives a row band and paints each cell; every row is in the hover group `row_group(id)`, for a cell shown only on its row's hover.
- `tree::{Tree, TreeState, TreeList}` — a tree list over flat `/`-separated paths (`\` read as `/`): folders are derived and listed before files at each level, names A–Z ignoring case or Z–A (`Order`). `Tree::build` folds each file's payload into every folder above it once, so a folder's aggregate (the owner's badge counts) covers its subtree and costs nothing per paint; build it off the UI thread for many entries and hand it to `TreeState::set_tree`. `TreeState` keeps the open folders by path, so a rebuild keeps them, plus the filter (a case-insensitive substring of the whole path through `matcher::find_all`, keeping the matching files and the folders above them and opening those folders), the order and the selected path. `TreeList` is a headless one-column `Table` (`headless`, `row_key`, `on_click`, `on_key`), so only the rows in view are laid out; it adds the indent, a folder's chevron and a file's `lead` slot (each `LEAD` wide, so every name at one depth starts at one x, and on the name's letters through `ink::mark`), a click on a folder toggles it, Left closes a folder or selects its parent, Right opens one or selects its first row; rows paint under `<id>-row-<path>` and the owner paints the rest of each row.
- `segmented::segmented` — a toggle of two or more `Segment`s (icon and/or label) in one bordered group, the chosen one filled; each option is `button::segment`, which shares `button::choice`'s fills; a click on another option calls `on_change(index)`, the owner keeping which is chosen.
- `matcher::{find_all, prefix, highlighted, count}` — case-insensitive substring/prefix matching, a result's highlighted label and a count badge.
- `settings_page::{SettingsPages, SettingsPage, row}` — a settings window's pages, registered by id with a title, an icon and a render fn, and one setting's row.
- `open::{scheme, allowed, refused, open, open_off_thread, LINK_SCHEMES, WEB_SCHEMES}` — every link or path opened with its handler: a terminal's Ctrl+click (`LINK_SCHEMES`), release notes and the sign-in page (`WEB_SCHEMES`), Open folder, Task Scheduler and the settings files; ShellExecuteW pumps its thread's messages, so `open` runs only off the UI thread (`open_off_thread`, or a thread of its own such as the sign-in's).
- `store::save_off_thread` — a `supraman_core::store::Save` written on the background executor, its outcome handed back to the owner.
- `nudge::{nudge, Nudge, Nudged}` — a coalescing wake-up for a loop on a gpui executor, instead of polling a flag.
- `themes` — Zed theme JSON over a base, the bundled themes, the terminal palette, `contrast` and the contrast floors (`fit_floors`); `themes::lanes`, the Git tab's ten lane colours: Supraman's `DARK` or `LIGHT` by the theme's appearance, a theme's style keys `gitman.lane.0` … `gitman.lane.9` (`#RRGGBB`; `null` or a bad value keeps Supraman's) over them, each lane moved to the nearest lightness that holds its floors on `editor.background` (its line 3:1, the text on its band `NAME_FLOOR`, on its pill and an avatar's initials `SECONDARY_FLOOR`) and reported like `fit_floors`' keys; `themes::attention`, every prompt band's fill: Supraman's `DARK` or `LIGHT`, or a theme's `supraman.attention`, moved to the nearest lightness where the theme's text on it holds `NAME_FLOOR` and it shows on `editor.background` (`SHOWS`); both kept per theme id by `themes::Kept`.
- `term_element` (`terminal_grid`, `TermFont`, `cell_metrics`) — the terminal grid painter for a `supraman_term::Terminal`; OSC 8 cells are underlined, and the pointer is a hand while Ctrl is held over a link.
- `lib.rs`: `init_globals`, `init_logger`/`Logger` (`supraman.log` via `append_capped`), `FrameProbe` — global setup and the probe the selftests print; the process's memory is `supraman_core::platform::process::memory`.

## Key flows

### A tab starting a session
1. `crates/supraman-app/src/view/hand_tab.rs` `FleetView::new_claude` → `hand_claude_in`: pushes a shell tab (or turns a prompt tab into it), then `hand::launch_locked` off the UI thread.
2. `crates/supraman-app/src/hand.rs` `launch_locked` picks the name under the lock (`Hands::pick`: `session_name`, `next_name`), mints a token outside it (below) and records it (`Hands::finish`), writing the config through `mcp_config_path`.
3. `view/hand_tab.rs` `extras_from` → `hand.rs` `extras`: from `upkeep::launch_config`, the plugin flags and `sm_allowed_tools`, the hook env (`SUPRAMAN_ROLE=hand`, `SUPRAMAN_SESSION`, `SUPRAMAN_REPO` the folder `holding` the cwd, a shown child inside one, the home vars) and the folder of `sm.exe`; with no plugin found, nothing and a notice.
4. `hand.rs` `Launch::script_with` builds `$env:Path = '<sm dir>;' + $env:Path; claude [--session-id <uuid>] --mcp-config <path> <plugin flags>` in a try/finally that deletes the config when claude exits; `shell_args_with` gives it as `-NoExit -EncodedCommand`, and `view/shells.rs` `powershell` runs those under `-ExecutionPolicy Bypass` in `supraman_core::platform::shell::terminal_powershell()`: `pwsh` from the first `PATH` folder holding it, else Windows PowerShell, by absolute path, looked up once per run.
5. `view.rs` `start_terminal_env` builds the PTY with `supraman_term::TerminalBuilder` and the hook env; `supraman_ui::term_element::terminal_grid` paints it. The session's hooks (`sm hook`) append to the home and its SessionStart injects `roles/hand.md`; the tree reads its events by session id (`HookSignal`). It is not `fm-`: the busy count leaves it out.
6. When the config file is gone (`Hands::ended`), `Hands::release` revokes the token.

Attach opens `claude attach <id>` (`view.rs` `attach`); `resume` runs `claude --bg --resume <id>` then attach for a background session, or `claude --resume` through `hand_claude_in` for an interactive one. A scheduled run gets no tab: `crates/supraman-claude/src/launch.rs` `LaunchSpec::argv` builds its `--bg` line.

### The poll
1. `crates/supraman-app/src/view/polls.rs` `Poller` loops every `REFRESH_EVERY` or when nudged; `read` reads the registry, one `list_sessions()` snapshot, the hook events and the schedules, which the app applies (and paints) before `Poller::tick` hands that snapshot to the upkeep. At start the version check runs beside setup and the first read.
2. `crates/supraman-app/src/upkeep.rs` `Upkeep::tick` loads `Settings` (the busy limit, the terminal), prunes hourly, ends a home's left controller records once (`end_controllers`), marks the scheduled runs of a queued sign-out, revokes deleted runs, drops lapsed hands and sweeps token-less configs, and reads the daemon hold the [+] tabs and resumes say.

### Folders and groups
1. `<home>/folders.toml` (`supraman_core::folders`) holds the sidebar's entries; the first load with no file makes it from the workspace files, once.
2. The poll reads it off the UI thread with the direct child folders of each folder that shows them and every listed or shown folder's kind and branch (`view/listed.rs` `read`, `fleet::on_disk`, a `fleet::Disk`), and `fleet::build` places every session by `supraman_claude::place_with` each frame from that and the poll's main-checkout table: the shown children are folders it weighs (`Entries::placed`), each a row after its parent (`FolderNode::parent`, no `pos`), so a session in `gaia\src` shows under the shown `gaia`, not its parent. A folder that shows its sub folders is watched alone (`listed::SubfolderWatch`, one `watch::Watcher` each, synced off the UI thread as the list changes, dropped when it hides them or goes); a change reads the list again (`FleetView::read_listed`).
3. The action bar's + offers Add Folder… (a folder picked with `folder_picker`, added at the top level's end) and Add Group… (a name in the sidebar's `GroupName` form); a group's row adds a folder at its end, renames it, or removes it (Remove Group's question: its folders to the top level, or gone from the list with it); every listed folder row offers Show/Hide sub folders and Remove Folder (a shown child is no entry: its menu has neither). A listed folder's row drags (`folder_edits::DraggedFolder`, its chip `tabs::chip`) onto a group's row (its end), another listed folder's row (before it, in that row's group or the top level) or the drop row and empty room below the tree (the top level's end), each target painted in the theme's drop-target colours while it is over it; `folder_edits::landing` says the `Place`, and a drop that changes nothing writes nothing. Each is a `FolderEdit` written by `folder_edits::write` (`folders::edit` off the UI thread; a read started before the write is not applied; a move, Show/Hide or Remove Folder of a position no longer holding its path refused), the toast saying what was done or why not. `sm folder add|remove|list` and `sm group add|rename|remove` edit the same file.

### Minting and re-minting
- Hands mint for tab sessions (`hand.rs` `launch_locked`); a scheduled run mints its own (`crates/sm/src/run.rs`).
- `crates/supraman-supervisor/src/mint.rs` `HttpMinter`: POST `/api/agent-sessions` (`replace: true`), PATCH to bind the claude session id, DELETE to revoke (404 counts as revoked). The bearer is the OAuth access token (`crates/supraman-supervisor/src/tokens.rs` `AppTokens`, role from `workman_role`).
- No file holds a token. `mint.rs` `Keeper` keeps the minted `wss_` token in the secret store under `mcp_token_key(name)` and writes the config `mcp_config_path` names with `headersHelper` = `sm mcp-header --home <home> <name>` (`write_mcp_config_helped`, the plugin servers beside Workman's, `--strict-mcp-config`).
- `sm mcp-header` (`mint.rs` `header`) branches off before any of `sm`'s start-up work and only reads the secret store: it prints the kept token's header, or `{"Authorization":"Bearer sm-no-token"}` when none can be read, always one line and exit 0 (empty stdout or a failed exit makes claude fall back to its own sign-in, which blocks every session); each run appends `<UTC time> <name> kept|placeholder: <why>` to `<home>/logs/mcp-header.log`. Re-minting a refused or expiring token is the app's `Keeping`.
- Records, each with the mint that made its token: `<home>/supervisor/hands.json`, and one `<home>/supervisor/runs/<name>.json` per scheduled run (`MintedSessions`).
- Re-mint: the app's `Keeping` (a refused or expiring token, a sign-in after a sign-out).
- Revoke (`mint.rs` `revoke`, the one end of a minted session: DELETE, unless the token is from another server than the sign-in's, then its config and kept token go) happens only when the session cannot come back: its claude session is deleted (`Absent`: missing from two non-empty `claude agents --all` snapshots in a row; `Upkeep::tick` → `revoke_deleted_runs` for scheduled runs, the app's Delete → `Hands::release_session` and a hand whose claude is gone for hands). A sign-out (`upkeep::sign_out`) is no end: the grant revoke takes every token minted under it, and `runs_signed_out` and `Hands::signed_out` mark those sessions, keeping their record, kept token and config for the re-mint after the next sign-in (`Keeping`). Stop, a run's end, quit, start and workspace remove keep token, config and kept token; Workman's idle window lapses an unused one.

### OAuth sign-in and refresh
1. `crates/supraman-app/src/view.rs` `FleetView::sign_in` → `crates/supraman-app/src/signin.rs` (`Auth::shared`: one `Auth` per home).
2. `crates/supraman-workman/src/auth.rs` `Auth::sign_in`: discovery, dynamic client registration, PKCE S256 on a loopback callback, the browser, the token request.
3. `Auth::access_token`: the held token while fresh, else a `refresh_token` grant under `<home>/oauth/refresh.lock` (shared with `sm`); `invalid_grant`/`invalid_client` forgets the stored token.
4. The refresh token lives in `crates/supraman-core/src/secret.rs` `FileStore`: `<home>/oauth/secrets/<hash>.bin`, DPAPI-encrypted for the current user, written with `write_atomic`. `<home>/oauth/servers.json` holds server metadata, no token. The access token is never logged and never written.

### The Workman read and its stream
1. `crates/supraman-work-view/src/work_view.rs` `WorkHub` (a gpui global) builds a `Client` with `Auth::bearer_for(origin)` and subscribes a `Stream`.
2. `crates/supraman-workman/src/stream.rs` `Stream::subscribe` holds `GET /api/stream` on its own thread with `Last-Event-ID` and our backoff; `WorkHub::on_signal` turns signals into `HubEvent`s.
3. `WorkView::on_hub` re-reads the open view through `crates/supraman-workman/src/client.rs` `Client`, debounced, off the UI thread; `crates/supraman-work-view/src/work_view/inbox.rs` `WorkInbox` listens to the same hub: one inbox per entry's `Target`, each row once per project with that project's name as its card's context, dismissals per project id. `WorkHub::reconfigure` runs after sign-in, sign-out or a URL change.

### The Git tab
The `git_view/` paths below are in `crates/supraman-git-view/src/`.
1. Open: a git folder row's graph icon (`view/left.rs`, hit key `git-graph-<ws>/<folder>`) → `view/git_tab.rs` `FleetView::open_git` → `open_or_focus`: one tab per folder, a second click focuses it. `GitView::open` takes the sizes a saved tab kept (`GitSizes`: column widths, the commit panel's width, its message height).
2. Load: `GitView::reload` runs `git_view/load.rs` `first` off the UI thread: git located, the refs, the status, the first page laid out with a fresh `Layout`. No git, a git older than `FLOOR` or no repository is a notice in the tab.
3. Page: the graph is a `table::Table`; its `on_near_end` runs `load::next` off the UI thread with the `Layout` and the walk carried over and appends the rows (`git_view/pages.rs` `Pages`, the tab's rows entity). A page that lands under a newer refresh is dropped by its token.
4. Select: a click or Up/Down selects a row; `selection_moved` hands a commit to `git_view/details/` `CommitPanel::show` (details, changed files and both file trees read off the UI thread, a late result dropped by its token) and the WIP row to `git_view/wip/` `WipPanel::show` (the status split into Unstaged and Staged). Each panel is its own entity right of the graph in a `SplitPane::render_second`.
5. Panels: the commit panel shows the header (sha, Copy), the message over its `HeightBar`, author, parents (a click selects that parent in the graph, `PanelEvent::Parent`), co-authors and counts, then the files: Path rows, the Tree with per-folder counts, or View all files with its filter (`details/files.rs` `path_list`, `tree_list`, `sort_button`, `view_toggle`, shared with the WIP panel). While a commit is selected and the tree is dirty, a banner over it counts the changes; its View Change selects the WIP row. Nothing stages, discards or commits (C146).
6. Diff: a file's click is `PanelEvent::File` with its `diff::Target` (`diff::Of`: a commit and its first parent, HEAD and the index, the index and the worktree, an untracked file against nothing, a conflicted one in File View). `GitView::open_diff` puts `git_view/diff/` `DiffView` in the graph's place: both sides read off the UI thread, File View | Diff View, Split | Inline, previous/next change (F7 / Shift+F7); Esc or × closes it to the graph, its selection and scroll as they were, and the next viewer starts in its mode and layout (`git_view/viewer.rs` `Viewer`, the tab's viewer entity).
7. Live refresh: `git_view/live.rs` asks `supraman_gitman::dirs` for the top and the git dirs, then watches the common git dir (200 ms) and the top (2 s) with `supraman_core::watch`. HEAD, `refs/`, `packed-refs`, `logs/HEAD` or another worktree's HEAD refresh the refs, the graph and the WIP; the index or a merge or rebase under way the WIP; lock files and objects nothing. The work dir's changes leave out the git dir and ask `ignored` (one `git check-ignore --stdin` per batch, on the watcher's thread), so ignored noise refreshes nothing. The window becoming active again refreshes everything once after 500 ms. `git_view/refresh.rs` reads as many commits as are loaded, keeps the selected commit selected and the commit at the top of the view where it was, refreshes the WIP lists in place and reloads an open working-tree diff whose file changed (`DiffView::reload`).

`git_view/probe.rs` is what a selftest reads of a tab (`GitView::probe`); the colours come from the theme (`colours.rs`, C152).

### Quit
1. `crates/supraman-app/src/tray.rs` Quit → `view.rs` `FleetView::quit`; closing the window only hides it to the tray.
2. Every attach tab detaches: `close_tab` → `start_detach` writes Ctrl+Z (`DETACH_INPUT`) and waits `DETACH_WITHIN`; a tab that does not detach cancels the quit.
3. `quit_step`: with no attach tab left, `hand::release_all_within` revokes the tokens of hands whose claude is gone, then `close_for_quit` closes the window. `open_hands` also releases them on `on_app_quit` and releases stale ones at start.

## Testing

- **cargo:** which profile, crates and worktree when: docs/DEVELOPING.md. A module's tests are `<module>/tests.rs`; a topic with no module of its own is `<parent>/tests/<topic>.rs`, declared from the parent's `tests.rs`; a crate's integration tests are in its `tests/`. GitMan's are one binary, `crates/supraman-gitman/tests/it` (`main.rs` declares each file as a module, so one link and one `Fixture::shared` per run): `cargo test --profile unit -p supraman-gitman --test it [<module>::<test>]`, its lib's alone `--lib`. Shared test helpers: `supraman_core::testing` (waits), `git_view::test_support` (every Git tab test's `open`, `click`, `painted`, …), `supraman_gitman::fixture` (`Fixture::{at, side, write_job, undo}`), `supraman_workman::fake::inbox_rows`. Fakes: `FakeWorkman` (`crates/supraman-workman/src/fake.rs`), a fake claude (`crates/supraman-claude/tests/fake_claude.rs`), `MemoryStore` for secrets.
- **Selftests** drive the real app on a home under `target/` (`crates/supraman-app/src/main.rs` `parse_args`, `crates/supraman-app/src/selftest.rs` `start`):
  - `supraman.exe --selftest`: the gate's UI run (`selftest.rs` `gate`, steps in `selftest_*.rs`), clicking through `HitTargets`. Step 1 writes a fixture group to the scratch home's folders.toml (two fake repos and this checkout's repo), never the user's folders. Steps 3–6 attach, close, scroll, select/copy/paste and follow a link in a real session's tab; 7–7y the Work tab, the left panel, first run, tabs and hotkeys, closed sessions, titles, refresh, search, marks, notices, delete, font and zoom, reopen, a [+] session, Start, the updater (7+u) the schedules (7y) and the Git tab on a fixture repo in the home (7g: open from the icon, a png diff, the minimum widths). Only what a unit test cannot see is checked here, and each step file opens with the line saying what; the watchdog fails the run after 300 s (frames slow while the display is off; 360 s with `SUPRAMAN_SHOTS`) and names the running step and the slowest ones.
  - `--selftest-perf`: what needs a quiet machine. Memory per open tab, the startup paint bound, the Work tab and idle frame budgets and the UI's responsiveness under load (7+r); watchdog 300 s. Not part of the merge gate.
  - `--selftest-shots` (with `SUPRAMAN_SHOTS`): the screenshots of fixture pages (`selftest_shots.rs`).
  - `--selftest-detach-shutdown`: attach tabs detach on quit (`detach_on_shutdown`); `--selftest-detach <n>` is a measurement run.
- **The clipboard mutex:** `crates/supraman-app/src/selftest_clipboard.rs` holds the named mutex `Local\Supraman-selftest-clipboard` while a selftest uses the clipboard, so parallel selftests on one machine do not clobber each other.
- **The gate**, run before every merge (commands: docs/DEVELOPING.md): the build, `cargo test`, `--selftest`, `--selftest-detach-shutdown`, and 0 leftover `fm-selftest` sessions afterwards (`claude agents --json --all`).
