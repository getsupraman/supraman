# Supraman architecture

For whoever is about to change Supraman, or to build another gpui tool (GitMan, FileMan) on its crates. What was
measured and why is in `docs/LEARNINGS.md`; what comes next is `docs/ROADMAP.md`; the keys are `docs/KEYS.md`.

## Crates

Dependencies point down this list only; nothing below depends on anything above it.

| Crate | Owns | Depends on |
|---|---|---|
| `crates/supraman-app` | The `supraman.exe` binary: `FleetView` (left tree, tabs, Work tab, Inbox), Settings window, tray, the supervisor's driver, hand sessions, the selftests. | every crate below |
| `crates/sm` | The `sm` CLI (`lib.rs`, shared by `sm.exe` and the console-less `smw.exe` a schedule's task runs): `workspace`, `sessions`, `want`/`unwant`/`roster`, `inbox`/`send`/`tell`/`messages`, `schedule` (with `fire`, `run`, `report` and `secret set`; `fire.rs` the checks and the script stage, `run.rs` the session stage), `work`, `hook`, `plugin install`, `probe`. Edits files the app acts on; drives no supervisor, but owns a scheduled run end to end (launch, watch, stop), and `mcp-header`, every session's `headersHelper`. | claude, core, supervisor, workman |
| `crates/supraman-supervisor` | Desired state per workspace, the pure `reconcile`, the executor (launch, resume, stop, mint, revoke), the shared busy budget, the Inbox rows (`NeedsYou`). No UI. | claude, core, workman |
| `crates/supraman-claude` | The only code that knows the `claude` CLI: `agents --json --all` and health, `--bg` launch, stop, rm, resume, the peer pipe, transcripts, the background-service check. | core |
| `crates/supraman-workman` | Every Workman read: the read API v1 client, `/api/stream`, the OAuth client, the HTTP agent. Read only (C21). A test fake behind the `fake` feature. | core |
| `crates/supraman-ui` | The gpui widgets and painters every Supraman binary shares: text input, buttons, banners, menu, confirm, toast, notices, tabs, hover card, split pane and height bar, column table, tree list, segmented toggle, matcher, settings pages, themes, the terminal grid painter, hit targets, logger, frame probes. | core, term |
| `crates/supraman-term` | The terminal model: Zed's `terminal` crate vendored onto alacritty (PTY, grid, input, mouse, links, scroll, search). No gpui views, no Supraman knowledge. A tab's env (`builder.rs` `insert_terminal_env`) is `TERM_PROGRAM=supraman` with `FORCE_HYPERLINK=1`, so claude writes a markdown link as OSC 8; the app opens a Ctrl+clicked link only through `view.rs` `link_target` (`http`, `https`, `mailto`, `file`). | — |
| `crates/supraman-core` | Plain Rust shared by all: the workspace registry, settings, files written safely, paths, time, process spawning, secrets at rest, the relay's files, hook events, names. No gpui, no claude, no HTTP. | — |

**Boundaries.**
- Only `supraman-claude` runs `claude` outside a terminal tab or parses its output; a tab runs `claude` in its PTY (`hand.rs`, `view.rs` `attach`).
- Only `supraman-workman` talks HTTP to Workman (the supervisor's `mint.rs` uses its `http_agent`). Nothing in Supraman writes Workman items; the MCP tools are the agents' write path (C21).
- `supraman-supervisor` takes a snapshot and returns actions; it never polls, never paints, and is ticked by the app.
- `supraman-core` and `supraman-term` have no Supraman crate dependencies; `supraman-ui` has no `claude` or Workman knowledge.
- `plugins/supraman` is not a crate: the Claude Code plugin loaded with `--plugin-dir` on sessions Supraman launches — `plugins/supraman/hooks/hooks.json` (exec-form `sm.exe hook <event>`), `plugins/supraman/roles/` (workspace, relay, repo), and the skills `workspace-controller` and `repo-controller`. See `plugins/supraman/README.md`.
- `spikes/term-spike` is not product: the m0/5 terminal spike, kept building against `supraman-term` and `supraman-ui`. Nothing depends on it.
- `probes/` holds the m0 measurement scripts; `scripts/` holds `scripts/release.ps1`, `scripts/shot.ps1` and `scripts/icon-gen/`.

## Shared components and helpers

Use these; do not grow a private copy (CLAUDE.md, C56). If none fits, extract one into the crate it belongs to and add it here and to CLAUDE.md.

### supraman-core (`crates/supraman-core/src/`)

- `fs::write_atomic` — every write of a file another process or thread may read (settings, registry, desired state, minted sessions, relay files). A unique temp file renamed over the target.
- `fs::lock_file` — an exclusive cross-process lock held while the returned file lives, around a read-modify-write (`DesiredState::update`, `refresh.lock`). `fs::try_lock_file` takes it only when free (`None` while held): a schedule's overlap lock.
- `fs::load_json_or_notice` — a JSON state file whose loss is a notice, not an error (stars, dismissals).
- `store::{JsonStore, Save}` — a small JSON state file held in memory, each in its own format (`starred.json`, `messages-dismissed.json`, the schedules' dismissed runs and approvals, `workstate-dismissed.json`): `load` reads it with `load_json_or_notice`, `edit` changes the value and returns the `Save` of a change, `Save::write` writes the newest value with `write_atomic` (a save overtaken by a later one writes nothing); the app runs it with `supraman_ui::store::save_off_thread`.
- `fs::append_capped` (with `fs::rotated`) — an append-only log rotated to `<file>.1` at a cap (event logs, `supraman.log`).
- `paths::{user_home, claude_dir}` — the user's home and claude's config dir (`CLAUDE_CONFIG_DIR`-aware); never read `USERPROFILE`/`HOME` yourself.
- `paths::{normalize, path_key, within, key_within, git_at, main_checkout, linked_git_dir}` — path comparison (`within`: a folder or below it, never a sibling sharing a prefix) and the `.git` file/dir walk without running git; `git_at` is the nearest `.git` (a repo's folder or a linked worktree's file) at or above a folder, the walk `branch_at`, `main_checkout` and the Details tab's worktree line share.
- `time::{now_ms, epoch_ms, modified_ms, hex6}` — epoch milliseconds and a scratch-name suffix.
- `time::{local, ago, clock, short, near, date_words, rfc3339_local, rfc3339_in}` — the times the UI shows, in this computer's zone: `ago` (rows, notices, Details), `clock` (the update line), `short` (a tab's hover card), `near` (next and last fires), `date_words` (Details, Approve), `rfc3339_local` (the Work tab's server times).
- `hex::{encode, decode}` — bytes as lowercase hex, two digits each, and back; every digest, key file name and MAC written as hex.
- `update::{Manifest, sign, verify, release_keys, sha256_file, signature_path}` — a release's `supraman-update.json` (its bytes as written are what is signed), its ed25519 signature file and the release keys compiled in from `update.pub`; `Manifest::check_zip` checks a downloaded zip. `sm release` writes and signs it; the app's update check and install use it.
- `prune::{prune, KEEP_MS}` — the one retention rule for what sessions leave in the home: event logs, relay outbox messages, sent and rejected drops, the `answered.json` entries of gone messages, and the schedules' rotated run records and spent run worktrees, after 30 days unmodified, and the state dirs of removed schedules; a drop still waiting is never removed. The supervision runs it hourly.
- `url::origin` (re-exported as `url_origin`; `supraman_workman::api_base`) — the one origin rule; origins key `servers.json` and the minted records.
- `process::{command, run, run_watched, git, shell_execute, alive, started, wait_any_exit}` — every child process outside the PTY: no console window, both pipes drained, a timeout that kills the child or its tree (`Kill::Child` for `claude`, whose tree holds the background service), ShellExecute, pid liveness. `run_watched` also kills the child when its `stop` returns true and returns what a killed child wrote (`Ended::{Exited, TimedOut, Stopped}`). Never `Command::new(..).output()` by hand.
- `secret::{SecretStore, FileStore, MemoryStore, default_store}` — every secret at rest: one DPAPI-encrypted file per key under `<home>/oauth/secrets`; `MemoryStore` in tests.
- `slug::{slugify, validate_name, FM_PREFIX}` — a repo or workspace name as a session-name part (a [+] session's `hand-<slug>` too); every Supraman session name starts with `fm-`.
- `slug::{name_char, is_session_name, is_safe_id}` — the other name rules: a typed character of a `validate_name` name (the Add workspace name field), a session name safe as a file-name part (`mcp_config_path`), a session id as a file name (`events`).
- `Settings::update` — every change to `settings.toml`: load, edit, save under `<home>/settings.lock`. `Settings::load_with_notices` when a bad key should be shown.
- `Settings` sections (`sessions`, `workman`, `appearance`, `terminal`, `window`, each a `Section`) — a key belongs in its table; another owner's table (a plugin's `[gitman]`) goes through `Settings::section`/`set_section` and survives every save.
- `Registry` (`load_all`, `list`, `home_from`) — the workspaces at `<home>/workspaces/<name>.toml`; `load_all` where one corrupt file must not hide the rest (the supervisor), `list` where it should stop the caller.
- `Workspace` (`model.rs`: `home`, `folders`, `scans`; `home()`, `contains`, `other_dirs`, `folder_at`, `add_folder`, `unique_folder_name`), `Folder` (`kind`: `git` or `plain`), `Scan`, `owners` — a workspace is a name, a home and a set of folders; a root-based file loads as one scan of its root. `owners` says which workspace a folder's supervised session belongs to (the first that has it enabled); `Registry::claim_folders` disables what another workspace owns.
- `discover`, `rescan`, `scan`, `branch_at` — a parent folder to a workspace and its folders, and each parent folder looked in again; shared by `sm workspace add` and the app's From a parent folder… and Rescan.
- `Registry::edit` (`edit.rs`: `Edit`, `Edited`; `Workspace::find_folder`) — one change to a registered workspace (add or remove a folder, enable, home, add or remove a scan; a removed scanned folder goes on its scan's `exclude`), read, checked against `owners` and saved under `<name>.toml.lock`; `DropGone` takes the folders a `rescan` no longer finds without skipping them; shared by `sm workspace new`/`add-folder`/… and the app's Edit folders… and Rescan (`view/folders.rs`).
- `schedule` (`schedule/`: `load`, `edit`, `approve`, `covered`, `verify_approval`, `effective_status`, `next_fire`, `previous_fire`, `next_fire_local`, `append_run`, `read_runs`, `runs`, `run_worktrees`, `command_file`, `base_prompt`, `preamble`, `run_stamp`, `run_id`, `session_name`, `run_worktree`, `DEFAULT_DENY`, `Profile::permission_mode`, `Permissions::{allowed, denied}`) — the scheduler's model (`docs/research/scheduler.md`): one TOML per workspace at `<home>/schedules/<ws>.toml`, changed only through `edit` under `<ws>.lock` + `write_atomic`. `edit` keeps `[schedule.approval]` as it was, sets `pending` and clears `action.worktree` when a covered field changes, and keeps `active` only while the approval's fingerprint is the current one. The fingerprint is the sha256 of the canonical covered JSON (trigger, action with a slash command's name and path, permissions, caps, policy, and the script's and prompt file's sha256); the approval's MAC is HMAC-SHA256 under `APPROVAL_KEY` in the `SecretStore`, created on the first `approve`. `approve` is called only from the window's Approve (C100). Next fires take the zone as a parameter: a wall time a DST change skips fires at the first minute after the gap, a repeated one fires once. Run records go through `append_capped` (1 MiB); `prune` removes the rotated ones, the state of removed schedules, and run worktrees with nothing uncommitted and no commit of their own. `SCHED_SLUG_PREFIX` keeps `repo_session_name` off the run names. A run works in its folder's checkout; only a schedule an earlier release saved with `worktree = true` gets a run worktree (`run_worktree`, `run_branch`), and only there may an `edit` run push its branch (`Permissions::allowed(always, run_branch)`). `Profile::Edit` reads `edit` and `worktree-edit` and fingerprints as `worktree-edit`, so earlier approvals verify. A run's names, its preamble (which says where the run works) and base prompt (a missing slash command or prompt file is `NoPrompt`, naming the folder), and a profile's `--permission-mode`, `--allowedTools` and `--disallowedTools` live here, so `sm schedule dry-run`, fire and the app agree; `sm`'s `schedule::run_spec` turns them into the run's `LaunchSpec`. `sync(&dyn Registrar, &SyncTarget, &Workspace, &[Schedule])` registers one Windows task per schedule that is `active` with a verifying approval, at `<task_root(home)>\<ws>\<id>` (`\Supraman` for `%APPDATA%\Supraman`, `\Supraman-<hex8 of sha256(path_key(home))>` for any other home), removes the rest of that folder and deletes it, then the root, when empty; it reads and writes nothing outside the folder. `task_xml` builds the definition (InteractiveToken, the run level, StartWhenAvailable for `catch_up = once`, WakeToRun, `smw.exe schedule fire --home … <ws> <id> --fingerprint …`); its `<Version>` is `definition_digest`, everything but the start date, so an unchanged task is left alone and a changed one (run level included) is registered again. `WindowsRegistrar` is COM `ITaskService`, each call on its own MTA thread; `FakeRegistrar` keeps the XML per path for tests and selftests (C101). The app is the only caller (C100). `covered_fields`/`covered_diff` flatten a covered JSON to sorted `field: value` leaves and diff two, which the window's Approve shows; `schedule_of_session` parses a run session's name back to its schedule id.
- `relay` (`send`, `tell`, `inbox_dir`, `outbox_dir`, `InboxWatcher`, …) — the relay's `inbox`/`outbox` files per workspace.
- `events` (`append_event`, `EventReader`, `role_injection`) — the hook events `sm hook` appends per session.
- `install::{exe_dir, sm_exe}` — the running exe's folder, where `supraman.exe`, `sm.exe` and `smw.exe` ship side by side, and the `sm.exe` in it; `schedule::smw_exe` and every app and `sm` lookup of either goes through them.
- `install_hook_exe`, `find_plugin_dir`, `sm_allowed_tools` — placing `sm.exe` in the plugin, and the `--allowedTools` rules that keep `sm` and the `agents` server's launch, list and stop from parking (every supervised session and every scheduled run).

### supraman-ui (`crates/supraman-ui/src/`)

- `text_input` (`TextInput`, `LineText`, `bind_keys`) — the one text input, single- or multi-line, on gpui's `EntityInputHandler`: selection, IME, dead keys, clipboard. Every text field uses it.
- `hit::{HitTargets, hit_target}` — every clickable element records its painted bounds under its key; the selftests click through these.
- `button::{bordered, outline, pill, icon, revealed, toolbar, toolbar_turning, ghost, small, choice, checkbox, tick, dimmed}` — every clickable button and tick box (`checkbox`: a fixed 14 px square under its key, ticked in the accent colour, one size either way, the caller adds the label and the click; `tick`: the same square as a read-only mark, a criterion's in the work view); the key is its element id, hover group and hit key; `toolbar_turning` turns its icon while work it started runs; `revealed` is a row's hover icon in a fixed slot: always laid out and painted, so nothing shifts and its hit key exists, shown while the row's group is hovered or the row is selected.
- `banner::{tinted, plain, dismissable, tint}` — every notice box: a status colour on its 0.12 tint.
- `fonts::{UI, MONO, icons}` — the UI's font families; never spell a family name in a view. The terminal's font is the user's (`Settings`).
- `menu::{ContextMenu, MenuItem, item}` — every right-click menu, generic over the owner's action type; items paint under `menu-<key>`; `MenuItem::under` starts a captioned section.
- `confirm::Confirm` — a question before an action that cannot be taken back (`ask`), or a report with only its OK (`report`); the owner places it.
- `toast::ToastSlot` — short feedback floating over a panel that goes by itself (`TOAST_FOR`); `show` marks a done action with ✓, `show_why` says why nothing was done.
- `notices::{NoticeKind, render, keep_dismissed, remove_one}` — a list of plain notices with a × each; the owner keeps the kinds and sources.
- `tabs::{tab_strip, TabHeader, DraggedTab, DraggedSession, reorder, cycled, sanitize}` — the tab strip with drag-to-reorder (`on_move(from, to)`; `DraggedTab { id }` is the payload any other drop target takes, `DraggedSession { session_id }` a session row's; a terminal pane takes both and pastes the session's SendMessage name), tab cycling, and a program's OSC title as a tab label; tab state and order stay with the owner.
- `hover_card::{HoverCard, tooltip}` — a hover card of a title and `label  value` rows.
- `icon::Icon` — Zed's Lucide icons (`assets/icons`, ISC, `THIRD_PARTY.md`) compiled in and tinted with a colour; `slotted` sizes one for a square slot so outlines and filled marks look one size.
- `tooltip::{Tooltip, LAST_SHOWN}` — a plain text tooltip; `LAST_SHOWN` is the text last shown, for the selftests.
- `clipped::{clipped, clipped_with, cut_at}` — a one-line label cut with an ellipsis (at the end or the middle) that carries its whole text as a tooltip while it is cut; `cut_at` is where a cut label was painted.
- `folder_picker::pick_folder` — the system folder picker; the owner gets the chosen folder after the window is activated again, so keys reach it whatever Windows gave the activation to.
- `split::SplitPane` — a resizable side-by-side split; the owner keeps and persists the width, the first panel's (`render`) or the second's (`render_second`). Its divider handle (`split::handle`, `DraggedDivider`) is also the table header's. `split::HeightBar` is a box over a short rounded bar that drags its height (min, max, double-click to the default), the owner keeping the height; its bar and the divider handle are one grab (`grip`), the same drag payload and end and reset calls.
- `table::{Table, TableState, Column, fit, drag, NearEnd}` — a table of columns over fixed-height rows on `gpui::uniform_list`, which lays out only the rows in view and measures one row, so a row count of tens of thousands, and pages appended to it, cost nothing per row (`KeyedList`'s `gpui::list` keeps a height per row and an anchor key, which variable rows need and these do not). The owner keeps the column widths and persists them from `on_resize(widths, done)`; `fit` gives the flexible column (else the last) the rest of the width, and `drag` resizes the column on a divider's side away from it, every column held at its min. `TableState` keeps the selection (click, Up/Down, `reveal`), the scroll and the focus; `on_near_end` is called, deferred, once per approach to the last row and again when rows arrive (`NearEnd`). Header, dividers, hover and selection take theme tokens; the owner gives a row band and paints each cell; every row is in the hover group `row_group(id)`, for a cell shown only on its row's hover.
- `tree::{Tree, TreeState, TreeList}` — a tree list over flat `/`-separated paths (`\` read as `/`): folders are derived and listed before files at each level, names A–Z ignoring case or Z–A (`Order`). `Tree::build` folds each file's payload into every folder above it once, so a folder's aggregate (the owner's badge counts) covers its subtree and costs nothing per paint; build it off the UI thread for many entries and hand it to `TreeState::set_tree`. `TreeState` keeps the open folders by path, so a rebuild keeps them, plus the filter (a case-insensitive substring of the whole path through `matcher::find_all`, keeping the matching files and the folders above them and opening those folders), the order and the selected path. `TreeList` is a headless one-column `Table` (`headless`, `row_key`, `on_click`, `on_key`), so only the rows in view are laid out; it adds the indent and chevron, a click on a folder toggles it, Left closes a folder or selects its parent, Right opens one or selects its first row; rows paint under `<id>-row-<path>` and the owner paints the rest of each row.
- `segmented::segmented` — a toggle of two or more `Segment`s (icon and/or label) in one bordered group, the chosen one filled; each option is `button::segment`, which shares `button::choice`'s fills; a click on another option calls `on_change(index)`, the owner keeping which is chosen.
- `matcher::{find_all, prefix, highlighted, count}` — case-insensitive substring/prefix matching, a result's highlighted label and a count badge.
- `settings_page::{SettingsPages, SettingsPage, row}` — a settings window's pages, registered by id with a title, an icon and a render fn, and one setting's row.
- `open::{scheme, allowed, refused, open, open_off_thread, LINK_SCHEMES, WEB_SCHEMES}` — every link or path opened with its handler: a terminal's Ctrl+click (`LINK_SCHEMES`), release notes and the sign-in page (`WEB_SCHEMES`), Open folder, Task Scheduler and the settings files; ShellExecuteW pumps its thread's messages, so `open` runs only off the UI thread (`open_off_thread`, or a thread of its own such as the sign-in's).
- `store::save_off_thread` — a `supraman_core::store::Save` written on the background executor, its outcome handed back to the owner.
- `nudge::{nudge, Nudge, Nudged}` — a coalescing wake-up for a loop on a gpui executor, instead of polling a flag.
- `themes` — Zed theme JSON over a base, the bundled themes, the terminal palette, `contrast` and the contrast floors (`fit_floors`).
- `term_element` (`terminal_grid`, `TermFont`, `cell_metrics`) — the terminal grid painter for a `supraman_term::Terminal`; OSC 8 cells are underlined, and the pointer is a hand while Ctrl is held over a link.
- `lib.rs`: `init_globals`, `init_logger`/`Logger` (`supraman.log` via `append_capped`), `FrameProbe`, `memory` — global setup and the probes the selftests print.

### supraman-workman (`crates/supraman-workman/src/`)

- `http_agent`, `read_reply`, `pct_encode`, `server_reason` (`http.rs`) — the HTTP agent, an answer read whole (status, headers, body; a body that cannot be read is a transport failure), path/query encoding and a refusal's reason for every Workman call, the mint and OAuth included.
- `Client` (`client.rs`) — the blocking read API v1 client (`overview`, `board`, `item`, `brief`, `inbox`, `journal`, `backlog`, `sessions`, `resolve`); GET only; its bearer comes from a `BearerSource` at each read; no error carries the token.
- `Stream` (`stream.rs`) — the `/api/stream` subscriber on its own thread: `StreamSignal::{Connected, Event, Lost}`; an event means "re-read".
- `Auth` (`auth.rs`) — the OAuth 2.1 native client: sign-in, `access_token`, refresh under `refresh.lock`, `bearer_for(origin)`.
- `health` — the unauthenticated `GET /health`.
- `fake::FakeWorkman` (feature `fake`) — the one test server for anything that talks HTTP to Workman: routes by `<METHOD> <target>` or by target, `set` to change an answer, `seen()` for each request's method, target, Authorization, Content-Type and body.
- `model` — the read API v1 shapes, lenient (v1 grows additively).
- `fake::FakeWorkman` (feature `fake`) — the read API and its OAuth server on 127.0.0.1 for tests and selftests.
- `secret` re-exports `supraman_core::secret`.

### supraman-claude (`crates/supraman-claude/src/`)

- `list_sessions`, `parse`, `Session::health`/`supervised_health` — `claude agents --json --all` and the health table (crate docs in `lib.rs`).
- `Claude` (`launch.rs`: `launch`, `resume`, `stop`, `rm`, `remove`, `find_by_name`), `LaunchSpec`, `resume_argv`, `new_session_id`, `name_taken` — the write side; every run goes through `supraman_core::process::run`.
- `mcp_config_path`, `write_mcp_config`, `workman_mcp_config` — a session's Workman config file under `<home>/mcp/`, with the session-name check; write, read and delete it through these.
- `check_supported`, `MIN_VERSION`, `TESTED_VERSION` (`cli.rs`) — the CLI version gate.
- `daemon_status`, `daemon_mismatch`, `is_elevated` (`daemon.rs`) — whether this process can reach claude's background service. `service_pid` (the roster's `supervisorPid`, since `claude daemon status` reads `NotRunning` from an unelevated process facing an elevated service), `pid_elevated`, `service_elevated` and `task_run_level` give a scheduled task's run level.
- `peer` — writing into a session's own message pipe (`docs/peer-messaging.md`); `human::send_from_human` picks the pipe or the relay.
- `proc_tree` — which claude session runs under a tab's shell.
- `transcript` (`Transcripts`: `scan_with` with progress, `with_cache`, `cached`; `first_prompt`; `Usage`, a session's input/output/cache tokens, each message once) — closed sessions from the transcript files, read only: head and tail of a new file, the grown part of a known one, on parallel readers; the file cache persists at `<home>/cache/transcripts.json` so a start shows its rows before any file is read.
- `forget::forget_transcript` — the one write under the claude dir (see delete confinement).
- `assign` — mapping sessions onto a workspace's folders (deepest folder, then a worktree's main checkout), then its home.

### supraman-supervisor (`crates/supraman-supervisor/src/`)

- `DesiredState` (`desired.rs`) — `<home>/supervisor/<workspace>.toml`; change it only through `update` (locked read-modify-write); `release` unwants the repo sessions of folders taken away, so the supervisor stops them.
- `Supervisor`, `tick_all`, `Budget` — one tick per snapshot; the rule table is the crate docs in `lib.rs`.
- `HttpMinter`, `Minter`, `MintedSessions` (`mint.rs`) — per-session Workman tokens.
- `AppTokens`, `bearer`, `workman_role` (`tokens.rs`) — the `TokenProvider` of the app and of `sm`: Supraman's OAuth sign-in as the mint's bearer.
- `LaunchConfig::launch_spec` (`executor.rs`) — a wanted session's `claude --bg` spec before its token; `Supervisor::launch` and a scheduled run (`sm`'s `schedule::run_spec`) both build theirs with it. `LaunchConfig::session_env` (the `SUPRAMAN_*` and home vars of its `--settings`) and `interactive_args` (`--plugin-dir`, `--allowedTools`) are the same pieces for a [+] session.

## Shared vs app-only

**GitMan and FileMan may reuse:** all of `supraman-core`, `supraman-ui`, `supraman-term`, `supraman-workman`, and `supraman-claude` if they run claude. Their settings live in their own `Settings` table (`Settings::section`/`set_section`) and their settings window registers its pages with `SettingsPages`.

**App-only (in `crates/supraman-app`, not for reuse):**

## Key flows

### A tab starting a session
1. `crates/supraman-app/src/view.rs` `FleetView::new_claude` → `hand_claude`: pushes a shell tab, then `Hands::launch_for` off the UI thread.
2. `crates/supraman-app/src/hand.rs` `Hands::launch_for` picks the name (`session_name`, `next_name`), mints a token (below) and writes the config through `mcp_config_path`.
3. `view.rs` `hand_extras` → `hand.rs` `extras`: from `supervise::launch_config` (the supervisor's pieces), the plugin flags and `sm_allowed_tools`, the hook env (`SUPRAMAN_ROLE=hand`, `SUPRAMAN_WORKSPACE` = the owning workspace, `SUPRAMAN_SESSION`, `SUPRAMAN_REPO` for a folder, the home vars) and the folder of `sm.exe`; with no plugin found, nothing and a notice.
4. `hand.rs` `Launch::script_with` builds `$env:Path = '<sm dir>;' + $env:Path; claude [--session-id <uuid>] --mcp-config <path> <plugin flags>` in a try/finally that deletes the config when claude exits; `shell_args_with` gives it as `-NoExit -EncodedCommand`, and `view.rs` `powershell` runs those under `-ExecutionPolicy Bypass` in `supraman_core::paths::terminal_powershell()`: `pwsh` from the first `PATH` folder holding it, else Windows PowerShell, by absolute path, looked up once per run.
5. `view.rs` `start_terminal_env` builds the PTY with `supraman_term::TerminalBuilder` and the hook env; `supraman_ui::term_element::terminal_grid` paints it. The session's hooks (`sm hook`) append to the home like a supervised session's and its SessionStart injects `roles/hand.md`; the tree reads its events by session id (`HookSignal`). The supervisor never wants, stops or counts it (it is not `fm-`).
6. When the config file is gone (`Hands::ended`), `Hands::release` revokes the token.

Attach opens `claude attach <id>` (`view.rs` `attach`); `resume` runs `claude --bg --resume <id>` then attach for a background session, or `claude --resume` through `hand_claude` for an interactive one. Supervised sessions get no tab: `crates/supraman-claude/src/launch.rs` `LaunchSpec::argv` and `resume_argv` build their `--bg` lines.

### The supervisor tick
1. `crates/supraman-app/src/view.rs` `Poller` loops every `REFRESH_EVERY` or when nudged; `read` reads the registry and one `list_sessions()` snapshot, which the app applies (and paints) before `Poller::tick` hands that same snapshot to the supervisor. At start the version check runs beside setup and the first read.
2. `crates/supraman-app/src/supervise.rs` `Supervision::tick` loads `Settings` and each `DesiredState`, syncs the relay, applies server changes and the daemon hold, then under `TICK` (and only while `ENABLED`) calls `tick_all`.
3. `crates/supraman-supervisor/src/budget.rs` `tick_all` builds one `Budget` and ticks each workspace's `Supervisor`.
4. `crates/supraman-supervisor/src/executor.rs` `Supervisor::tick`: re-mint stops, resume confirmation, memory, `reconcile` (`crates/supraman-supervisor/src/reconcile.rs`, pure), then launch / resume / stop, revocation, and the `NeedsYou` rows.

`sm want`/`unwant` (`crates/sm/src/repos.rs`) and the app's Start/Stop (`supervise.rs` `start_workspace`) only edit `DesiredState` through `update`; the next tick acts on it.

### Adding and editing a workspace
1. The left panel's folder button opens From a parent folder… and Custom workspace… (`view/manage.rs` `open_add_menu`); each opens `view/workspace_dialog.rs` `WorkspaceDialog` (`Mode::Parent`, `Mode::Custom`), held in `FleetView::adding`. Its rows are `view/folder_list.rs` `FolderList`: name (branch), path, [home], ×, the include tick on a parent's subfolders, `supervised in <ws>` from `owners`, and the add row (path, Browse, Add), whose folder is read off the UI thread.
2. A parent's subfolders come from `discover` off the UI thread. Save registers the workspace (`check_new`, `claim_folders`, `save`) off the UI thread: a parent's ticked folders with one `Scan` of it whose `exclude` holds the unticked and removed ones; a custom workspace's folders with none.
3. Edit folders… (`view/folders.rs` `edit_folders`) opens the same dialog as `Mode::Edit(workspace)`, the name shown, not editable. Nothing is written until Save: `edits_of` turns the list into `Edit::RemoveFolder`, `AddFolder` and `SetHome`; `request_edits` asks first (`Confirm`) when one stops a wanted supervised session (`stops`); `apply_edits` → `edit_all` runs them through `Registry::edit` off the UI thread and releases the removed folders' sessions (`DesiredState::release`: stop, never rm); the toast is `summary` and `edited_note`. Cancel or Esc discards.
4. Rescan (`rescan_workspace` → `rescan_offer`, off the UI thread) of a workspace with a parent folder: `rescan` looks in it again; the folders gone from disk go at once (`Edit::DropGone`, named in the toast), and the new ones open the edit dialog as unticked rows. Save adds the ticked ones; an unticked one is offered again at the next Rescan; only × on a folder puts it in the parent's `exclude`. A workspace without a parent folder answers that it has none to look in.

### Minting and re-minting
- The supervisor mints for `fm-` sessions (`executor.rs` `Supervisor::mint`, from `launch`, and `remint` before every Resume); hands mint for tab sessions (`hand.rs` `Hands::launch_for`).
- `crates/supraman-supervisor/src/mint.rs` `HttpMinter`: POST `/api/agent-sessions` (`replace: true`), PATCH to bind the claude session id, DELETE to revoke (404 counts as revoked). The bearer is the OAuth access token (`crates/supraman-supervisor/src/tokens.rs` `AppTokens`, role from `workman_role`). A scheduled run mints its own token the same way (`crates/sm/src/run.rs`).
- No file holds a token. `mint.rs` `Keeper` keeps the minted `wss_` token in the secret store under `mcp_token_key(name)` and writes the config `mcp_config_path` names with `headersHelper` = `sm mcp-header --home <home> <name>` (`write_mcp_config_helped`, the plugin servers beside Workman's, `--strict-mcp-config`).
- `sm mcp-header` (`mint.rs` `header`) prints the kept token after one `ping` POST to the MCP URL with it (`supraman_workman::refuses`); a 401/403 or a missing kept token mints afresh with `replace` from the name's record (`MintedSessions::find`) and Supraman's sign-in, keeps it and prints it, so claude's own retry after a 401 heals the connection.
- Records, each with the mint that made its token: `<home>/supervisor/<workspace>.sessions.json`, `<home>/supervisor/hands.json`, and one `<home>/supervisor/runs/<name>.json` per scheduled run (`MintedSessions`).
- Re-mint: every Resume; the Re-mint remedy on a `TokenExpired` or `OtherServer` row (`Supervisor::retry` → `stop_for_remint`, then resume); a server change (`Supervisor::server_changed`).
- Revoke (`mint.rs` `revoke`, the one end of a minted session: DELETE, unless the token is from another server than the sign-in's, then its config and kept token go) happens only when the session cannot come back: its claude session is deleted (`Absent`: missing from two non-empty `claude agents --all` snapshots in a row; `Supervisor::tick` for supervised sessions, `Supervision::tick` → `revoke_deleted_runs` for scheduled runs, the app's Delete → `Hands::release_session` and a hand whose claude is gone for hands), or a sign-out (`supervise::sign_out`: the grant revoke takes every token minted under it, and `Supervisor::signed_out`, `forget_runs` and `Hands::signed_out` forget them). Stop, unwant, give-up, a run's end, quit, start and workspace remove keep token, config and kept token; Workman's idle window lapses an unused one.

### OAuth sign-in and refresh
1. `crates/supraman-app/src/view.rs` `FleetView::sign_in` → `crates/supraman-app/src/signin.rs` (one `Auth` per home).
2. `crates/supraman-workman/src/auth.rs` `Auth::sign_in`: discovery, dynamic client registration, PKCE S256 on a loopback callback, the browser, the token request.
3. `Auth::access_token`: the held token while fresh, else a `refresh_token` grant under `<home>/oauth/refresh.lock` (shared with `sm`); `invalid_grant`/`invalid_client` forgets the stored token.
4. The refresh token lives in `crates/supraman-core/src/secret.rs` `FileStore`: `<home>/oauth/secrets/<hash>.bin`, DPAPI-encrypted for the current user, written with `write_atomic`. `<home>/oauth/servers.json` holds server metadata, no token. The access token is never logged and never written.

### The Workman read and its stream
1. `crates/supraman-app/src/work_view.rs` `WorkHub` (a gpui global) builds a `Client` with `Auth::bearer_for(origin)` and subscribes a `Stream`.
2. `crates/supraman-workman/src/stream.rs` `Stream::subscribe` holds `GET /api/stream` on its own thread with `Last-Event-ID` and our backoff; `WorkHub::on_signal` turns signals into `HubEvent`s.
3. `WorkView::on_hub` re-reads the open view through `crates/supraman-workman/src/client.rs` `Client`, debounced, off the UI thread; `crates/supraman-app/src/work_view/inbox.rs` `WorkInbox` listens to the same hub. `WorkHub::reconfigure` runs after sign-in, sign-out or a URL change.

### Quit
1. `crates/supraman-app/src/tray.rs` Quit (asking first when workspaces are started) → `view.rs` `FleetView::quit`; closing the window only hides it to the tray.
2. Every attach tab detaches: `close_tab` → `start_detach` writes Ctrl+Z (`DETACH_INPUT`) and waits `DETACH_WITHIN`; a tab that does not detach cancels the quit.
3. `quit_step`: with no attach tab left, `hand::release_all_within` revokes the tokens of hands whose claude is gone, then `close_for_quit` closes the window. `open_hands` also releases them on `on_app_quit` and releases stale ones at start.
4. Supervised `--bg` sessions keep running; the supervisor only stops ticking.

## Testing

- **cargo:** `cargo test --workspace`. Unit tests sit beside the code; integration tests in each crate's `tests/`. Fakes: `FakeWorkman` (`crates/supraman-workman/src/fake.rs`), a fake claude (`crates/supraman-claude/tests/fake_claude.rs`), `MemoryStore` for secrets.
- **Selftests** drive the real app on a home under `target/` (`crates/supraman-app/src/main.rs` `parse_args`, `crates/supraman-app/src/selftest.rs` `start`):
  - `supraman.exe --selftest`: the gate's UI run (`selftest.rs` `gate`, steps in `selftest_*.rs`), clicking through `HitTargets`. Step 1 registers a fixture workspace (two fake repos and this checkout's repo), never a scan of the user's folders. Steps 3–6 attach, close, scroll, select/copy/paste and follow a link in a real session's tab; 7–7y the Work tab, the left panel, first run, tabs and hotkeys, closed sessions, titles, refresh, search, marks, messages and notices, delete, font and zoom, reopen, a [+] session, Start, the updater (7+u) and the schedules (7y). Only what a unit test cannot see is checked here; the watchdog fails the run after 200 s (360 s with `SUPRAMAN_SHOTS`) and names the running step and the slowest ones.
  - `--selftest-perf`: what needs a quiet machine. Memory per open tab, the startup paint bound, the Work tab and idle frame budgets and the UI's responsiveness under load (7+r); watchdog 300 s. Not part of the merge gate.
  - `--selftest-supervise`: the supervisor against real `claude --bg` sessions (`crates/supraman-app/src/selftest_supervise.rs`), 5 a run. a sets up the testbed; b Start launches the workspace session with its role tag and skills; c a `claude stop` is resumed by the supervisor; d an untrusted folder raises a trust row; e a parked session shows `blocked`; g the tray's Stop all; h closing the window keeps supervising; w `sm want` launches a repo session and `sm workspace remove-folder` stops it; r direct pipe sends and the relay fallback; t a DECIDE answered through the Inbox's box and an APPROVE? approved. Watchdog 420 s.
  - `--selftest-supervise --release`: adds step y, Adopt forking a real session with `--resume <uuid> --fork-session` (7 sessions); only the release gate runs it (docs/RELEASE.md).
