# Supraman (AutoWork)

Native Rust/gpui app that supervises workspaces of Claude Code sessions. Work runs as a controller queue in Workman project `supraman`; `docs/LEARNINGS.md` holds what each unit found.

## Use shared components, never hidden hand-rolled ones

**This binds every agent and subagent working in this repo — brief subagents on it when you delegate.**

Before you build something generic yourself (a text input, a list, a dialog, an HTTP or OAuth client, a file watcher, a process helper, a parser, …), search for a shared one and use it. If none fits, extract a shared one into the crate it belongs to and list it below. Do not grow a private copy inside a feature. A unit that keeps a local implementation says why in its report.

Reusable components (crates, boundaries, flows and when to use each: `docs/ARCHITECTURE.md`):

- `supraman_ui::text_input`: the one text input (EntityInputHandler: selection, IME, clipboard); every text field uses it; `submit_apart` makes Ctrl+Enter `InputEvent::Submit`, apart from Enter's `Confirm` (the commit message's fields). `text_input::filter_box` is every filter field: the input and the subscription that hands its owner the text after each edit (the commit panel's Filter files, the ref panel's Filter refs).
- `supraman_ui::button::{bordered, outline, pill, icon, revealed, reveal, toolbar, toolbar_turning, ghost, small, choice, checkbox, tick, dimmed}`: every clickable button and tick box (`checkbox`: a fixed 14 px square, ticked in the accent colour, the caller adds the label; `tick`: that square as a read-only mark, such as a criterion's; `dimmed`: one that cannot act now, its click a no-op then); the key is its id, hover group and hit key; `toolbar_turning` turns its icon while work it started runs; `revealed` is a row's hover icon, always laid out and painted (no shift, hit key kept), shown while its row's group is hovered or the row is selected; `reveal` shows any button that way (the WIP panel's Stage File).
- `supraman_ui::banner::{tinted, plain, dismissable, tint}`: every notice box; a status colour on its 0.12 tint (m5/26 contrast).
- `supraman_ui::hit::{HitTargets, hit_target, SNAP}`: every clickable element records its painted bounds under its key; the selftests click through these (`Hit::fully_visible` allows `SNAP`, a device pixel of snapping past the clip).
- `supraman_ui::fonts::{UI, MONO, icons, figures}`: the UI's font families; never a family name spelt out in a view; `figures` is the UI font with tabular figures for dates and shas (the graph's columns, the commit panel's shas).
- `supraman_ui::menu::{ContextMenu, MenuItem, item}`: every right-click menu, generic over the owner's action type; items paint under `menu-<key>`; `MenuItem::under(caption)` starts a section (a rule and a caption).
- `supraman_ui::confirm::Confirm`: every question before an action that cannot be taken back (`ask`), and every report with only its OK (`report`); the owner places it.
- `supraman_ui::toast::ToastSlot`: every short feedback that floats over a panel and goes by itself (`show` for done, `show_why` for why nothing was done).
- `supraman_ui::notices::{NoticeKind, render, keep_dismissed, remove_one}`: every list of plain notices with a × each; the owner keeps the kinds and their sources.
- `supraman_ui::tabs::{tab_strip, TabHeader, DraggedTab, DraggedSession, reorder, cycled, sanitize}`: the tab strip with drag-to-reorder (`on_move(from, to)`), the dragged tab's and session row's payloads for any other drop target, tab cycling, and a program's OSC title as a tab label; tab state, order and detach stay with the owner.
- `supraman_ui::hover_card::{HoverCard, tooltip}`: every hover card of a title and `label  value` rows.
- `supraman_ui::icon::Icon`, `supraman_ui::tooltip::{Tooltip, LAST_SHOWN}` and `supraman_ui::clipped::{clipped, clipped_with, clamped, cut_at, path_label}`: every icon (Zed's Lucide SVGs in `supraman-ui/assets/icons`, `svg` or `slotted`), every plain text tooltip, and every one-line label cut with an ellipsis that shows its whole text as a tooltip while cut (`clamped`: the same over up to n wrapped lines, the Inbox card's title; `path_label`: a `/` path's folder muted and cut, its name bright: the diff header, the changed files' Path rows); the selftests read `LAST_SHOWN` and `cut_at`.
- `supraman_ui::placeholder::placeholder`: every pane's centred title and muted details while it has nothing else to show (the Git tab's load and problem, the commit and WIP panels, the diff viewer).
- `supraman_ui::folder_picker::pick_folder`: every system folder picker; the window is active again before the owner gets the folder (From a parent folder…, the folder list's Browse).
- `supraman_ui::split::{SplitPane, HeightBar, Stack, Pane, StackState}`: every resizable side-by-side split, every box whose height a bar under it drags (min, max, double-click resets), and every column of stacked panes whose borders drag height between the open neighbours (`Stack`: a closed pane is its header, each open one held at `min`, a double-click shares evenly; GitKraken's ref sections); the owner keeps and persists the width (the first panel's, or with `render_second` the second's) or heights; all share one grab (`split::handle`'s drag).
- `supraman_ui::table::{Table, TableState, Column, fit, drag, clamp, NearEnd, row_group}`: every table of columns over many fixed-height rows (`uniform_list`, only the rows in view): a header whose dividers drag to resize (SplitPane's handle) with GitKraken's rule (`table/widths.rs`: columns fill the width exactly, a drag refits only the columns right of its divider, a narrower table takes from the right, a wider one gives back to columns below their preferred width, the rest to the last; a column's min, optional max, and its header icon at a threshold); the owner keeps and persists the preferred widths `on_resize` reports at a drag's end, the table the current ones, a painter per cell, the owner's row band, one selected row (click, Up/Down, `reveal`), the scroll (`scroll_top`, `set_scroll_top`), `on_near_end` once per approach to the last row, `row_group(id)` for a cell shown on its row's hover; `headless`, `row_key`, `on_click` and `on_key` for a list built on it (the tree); hit keys `<id>-col-<column>`, `<id>-divider-<column>`, `<id>-row-<n>`.
- `supraman_ui::tree::{Tree, TreeState, TreeList, Row, Item, Order, LEAD}`: every tree list over flat `/` paths (folders derived, listed first, A–Z or Z–A, or in the entries' own order with `Tree::build_given`/`set_entries_given`, as the Git tab's ref panel interleaves them): a folder's aggregate folded over its subtree once per build (`TreeState::aggregate` reads it), open folders kept by path in `TreeState` across rebuilds, Expand/Collapse All, a filter on the whole path (or the owner's `match_with` on a file's payload) that opens the folders holding a match, the owner's row painter (a file's starts with a `LEAD`-wide slot, its mark, where a folder has its chevron, so names at one depth align), selection with Up/Down/Left/Right, `on_toggle` when a click or key opens or closes a folder and `closed()` the folders shut (the ref panel keeps them per repo), `hide_roots` for a list whose top folders the owner paints (the ref panel's section panes); `TreeList::mark` for a slot at every row's left edge whatever its depth (the ref panel's marks); its rows are a headless `Table` (only the rows in view), hit keys `<id>-row-<path>`.
- `supraman_ui::segmented::{segmented, Segment}` (options are `button::segment`, `choice`'s fills): every toggle of two or more options in one bordered group, such as Path | Tree; each option paints under `<id>-<key>`.
- `supraman_ui::matcher::{find_all, prefix, subsequence, highlighted, count}`: case-insensitive matching (`subsequence` the fuzzy one) and a results list's highlighted label and count badge.
- `supraman_ui::palette::{Palette, Entry, Mode, PaletteEvent, Paint, Rank, ranked, ranked_by, fuzzy, path_fuzzy, marks_in}`: every Ctrl+P palette (the Work tab's, the Git tab's `git_view/find`): a query box (`text_input`), the owner's `Entry`s matched by `subsequence` best first (`set_rank`: `ranked_by` with a `fuzzy`/`path_fuzzy` fit and a boost for ties, such as the Git palette's frecency), the owner's remote hits after them (`set_remote`, dropped once the query moved on), `Mode`s searching other sources under a chip (entered by an `Entry::mode` row, a typed prefix or `enter_mode`, left by Backspace on an empty query; `set_mode_entries` ends a mode's spinner), an `Entry::dimmed` row listed dimmed with its reason as tooltip and a no-op pick, a `keyed_list` of rows the owner's `Paint` draws (`marks_in` cuts the marks per field), Up/Down, Enter or a click is `PaletteEvent::Open`, Esc or a click outside `Close`, each edit `Query`; the owner places it; rows paint under `<id>-row-<key>`, the selected one also `<id>-selected`, the chip `<id>-chip`.
- `supraman_ui::details::{Page, Section, Line, render, text, index_of, OnLink}`: every details page in a tab: a title with a status pill, sections of `label  value` rows, links (`Section::link`, followed by the page's `on_link`), paragraphs, long text with Copy, ticked lines with a muted note (`Section::check`, a criterion and its evidence), and an actions bar (none when empty); `over` is a line above the title (a ref and its actions), `bar` a held row under it (chips, a tab bar); the owner builds the sections and keeps the `ScrollHandle`; `text` is what a test reads.
- `supraman_ui::marks::{Mark, dot, squares, progress_line, SQUARES_MAX}`: a state's mark: a filled or hollow (`Mark::Ring`, waiting) dot, a strip of one square per item (a plain bar over `SQUARES_MAX`), and a thin line of coloured shares; the owner maps its states to marks on the theme's status colours (the Work tab's legend: `work_view::state::StateKey::mark`).
- `supraman_ui::settings_page::{SettingsPages, SettingsPage, row}`: a settings window's pages, registered by id with a title, an icon and a render fn, its page list, and one setting's row.
- `supraman_ui::open::{allowed, refused, document, refused_file, file_url_path, open, open_off_thread, LINK_SCHEMES, WEB_SCHEMES}`: every link or path opened with its handler: the scheme allowlist (`LINK_SCHEMES` for a program's links, `WEB_SCHEMES` for web pages), the refusal's words, `document` refusing a file that runs, scripts, installs or links something (a fixed list plus `PATHEXT`, or no extension) while folders and documents open, a `file:` URL as its path through the same check, and ShellExecuteW never on the UI thread (`open_off_thread`); never `cx.open_url`, `open_with_system` or a `shell_execute("open")` of your own.
- `supraman_ui::nudge::nudge`: a loop on a gpui executor that sleeps until nudged or timed out, never a timer polling a flag.
- `supraman_core::watch::{Watcher, Watch, Batch, Stopped}`: the one file watcher (Zed's `notify`, the OS's notifications): paths watched recursively or alone, each batch of changed paths delivered on the watcher's own thread a debounce after its first change, everything stopped when the `Watcher` drops (`stopped()` says when its thread and OS watch are gone); never a polling timer or a `notify` of a crate's own. The Git tab follows its repo with it (`git_view/live.rs`).
- `supraman_ui::keyed_list::KeyedList`: every long list that lays out only its rows in view (`gpui::list`), a key per row so the row on top stays on top as rows come and go, and `reveal(hit)` to scroll to the row a hit key belongs to; the sidebar uses it.
- `supraman_ui::stall::{section, watch, take}`: every UI-thread section worth timing (`section(label)`, logged over 100 ms), the foreground heartbeat that logs a held UI thread with the sections that ran (`watch`, started once in `main`), and a selftest's read of both.
- `supraman_ui::themes` (`contrast`, `secondary` (the one secondary text colour), `fit_floors`, `lanes`, `syntax`: a theme's code colours over Supraman's dark or light defaults, held to `SYNTAX_FLOOR`; both fit a colour with the one `nearest_holding` lightness search) and `supraman_ui::term_element::terminal_grid`: the themes with their contrast floors, the Git tab's lane palette (`gitman.lane.0`–`9` overrides), and the terminal painter.
- `supraman_core::fs::write_atomic`: every write of a file another process or thread may read or write (settings, registry, supervisor and relay files); never a fixed `*.tmp` and rename by hand.
- `supraman_core::fs::lock_file`: an exclusive cross-process lock held while the returned file lives, around a read-modify-write (`refresh.lock`, `DesiredState::update`); never a check-then-write retry loop. `try_lock_file` is the same without the wait (`None` while held): a schedule's overlap lock.
- `supraman_core::fs::heavy_job_lock`: the machine-wide lock of one heavy job; every selftest mode holds it for its run, and `scripts/heavy-lock.ps1` runs a cargo build or test under the same file, so builds and selftests never overlap; it cleans the workspace members when the shared target dir last built another worktree (`target\.last-workspace`), so build every cargo command through it.
- `supraman_core::fs::load_json_or_notice`: a JSON state file whose loss is shown to the user as a notice, not an error (stars, dismissals).
- `supraman_core::store::{JsonStore, Save}` and `supraman_ui::store::save_off_thread`: a small JSON state file held in memory (stars, the dismissed messages, runs and approvals, the Workman inbox's dismissals): `load` over `load_json_or_notice`, `edit` returns the `Save` of a change, written with `write_atomic` off the UI thread, the newest value last; never a store of your own.
- `supraman_core::fs::append_capped`: an append-only log that rotates to `<file>.1` at a size cap (event logs, `supraman.log`).
- `supraman_core::prune::prune`: the one retention rule for event logs and relay files left in the home; never a cleanup of your own.
- `supraman_core::Settings::update`: every change to `settings.toml` (load, edit, save under `<home>/settings.lock`); `Settings::load_with_notices` when a bad key should be shown.
- `supraman_core::workman_server::{load, load_from, save, ServerJson, NOT_SET_UP, validate_workman_url}` with `supraman_core::paths::workman_server_json` (`set_workman_server_json_for_selftest`, once, before any read): `~/.workman/server.json` (C183), the one source of the Workman URL; missing or unusable is a refusal that says to run `/workman:setup` and nothing dials, another `mcpName` a warning; `Auth::server`/`configured_origin`/`save_server` read and write it for the app and `sm` (`Auth::with_store` alone has no path; a test passes its own with `with_server_json`); without it sessions launch strict with no `workman` entry (`Keeper::launch_unminted(spec, None)`).
- `supraman_core::paths::{claude_json, user_mcp_server, set_claude_json_for_selftest}` with `workman_server::claude_warning`: claude's user config where claude looks for it (`<CLAUDE_CONFIG_DIR or user home>/.claude.json`, the legacy `<claude_dir>/.config.json` while only it has content) and the one reader of it: a top-level `mcpServers` entry's `url` only, never `headers` or any other key; `claude_warning` says when the `workman` entry is missing or is not server.json's `<origin>/mcp` (Settings → Workman, via the app's `workman_setup::check_server` off the UI thread); never `claude mcp get/list`.
- `supraman_core::Settings` sections (`sessions`, `appearance`, `terminal`, `window`, `updates`, each a `Section`; a former `[workman]` or `[workstate]` table is kept as another owner's, never read): a key belongs in its table; another owner's table (a plugin's `[gitman]`) goes through `Settings::section`/`set_section` and survives every save; `section_or_notice` when a bad table must be said (GitMan's `Located::BadSetting`).
- `supraman_core::secret::{SecretStore, FileStore, MemoryStore, default_store}`: every secret at rest (DPAPI file per key under `<home>/oauth/secrets`); `MemoryStore` in tests; `supraman_workman::secret` re-exports it.
- `supraman_core::Registry::load_all`: every list of workspaces that must survive one corrupt file (the supervisor); `list` only where one failure should stop the caller.
- `supraman_core::{slugify, validate_name, FM_PREFIX}`: a name as a session-name part; every Supraman session name starts with `fm-`.
- `supraman_core::{name_char, is_session_name, is_safe_id}` (`slug.rs`): the name rules: a typed character of a `validate_name` name (a name field's filter), a session name safe in a file name (`mcp_config_path`), a session id as a file name (event logs).
- `supraman_core::{discover, rescan, scan}`, the relay files (`send`, `tell`, `inbox_dir`, `outbox_dir`) and the hook events (`append_event`, `EventReader`): shared by `sm` and the app.
- `supraman_core::home::{home_from_env, env_home, home_env}` (`HOME_VAR` `SUPRAMAN_HOME`): the Supraman home, `%APPDATA%\Supraman` by default; `env_home` for a hook's or session's home; `home_env` for a child's env. Never read the var yourself.
- `supraman_core::paths::{user_home, claude_dir}`: the user's home and claude's config dir (`CLAUDE_CONFIG_DIR`-aware); never read `USERPROFILE`/`HOME` yourself.
- `supraman_core::paths::{normalize, path_key, within, git_at, main_checkout, linked_git_dir}`: path comparison (`within` for "this folder or below") and the `.git` file/dir walk without running git (`git_at`: the nearest `.git` at or above a folder; `branch_at`, `main_checkout` and a Details tab's worktree line use it).
- `supraman_core::paths::pwsh_command`: the file pwsh runs for a bare command name (per `PATH` folder, `.ps1` first, then `PATHEXT`), what a [+] tab's `claude` resolves to.
- `supraman_core::paths::{pathext, folders_holding, executable, executable_on_path}`: the one `PATHEXT` reader (Windows' default when unset or empty), the `PATH` folders that hold a file, and the program a bare name starts (GitMan's git); never a `split_paths` or `var("PATHEXT")` of your own.
- `supraman_core::paths::{PowerShell, powershell, job_powershell, windows_powershell, terminal_powershell, script_powershell}`: every PowerShell Supraman starts, by absolute path (`pwsh` from the first absolute `PATH` folder, else `%SystemRoot%`'s Windows PowerShell) with its short `name` for a title; `terminal_powershell` (looked up once) for every tab and selftest shell, `script_powershell` (Windows PowerShell in place of a Store alias of pwsh, which a job object misses) for `sm fire`'s `.ps1`; never a bare `pwsh` or `powershell`.
- `supraman_core::shells::{detect, detect_on, Shells, Shell, ShellSetting, Machine}`: this machine's shells for a plain terminal tab (pwsh, Windows PowerShell, cmd, a Developer PowerShell and Command Prompt per `vswhere` install, each WSL distro but `docker-desktop*`), each a label, an absolute program and its args; `detect` blocks (off the UI thread); `Shells::for_settings` resolves `[terminal] shell`/`shell_args` with a notice and `auto` for a value it cannot start; `Shell::short` titles a tab. In supraman-app `view/shells.rs` starts every plain tab (`default_shell`, `open_plain`, the ⌄ menu, `command` with cmd's spaced arguments quoted) and `Tab::started` is what a tab's terminal runs (saved with a plain tab). Tabs that start or attach claude stay on PowerShell (C113).
- `supraman_core::{Registry::edit, Edit, Edited}`: every change to a registered workspace's folders, home and scans (`sm workspace add-folder`/`remove-folder`/`enable`/`disable`/`set-home`/`add-scan`/`remove-scan`, the app's Edit folders… and Rescan, whose gone folders go by `Edit::DropGone`), under the file's lock; a removed folder's session goes through `DesiredState::release`.
- `supraman_core::{Workspace, Folder, owners}` and `Registry::claim_folders`: a workspace's home, folders (git or plain) and scans; `home()` for where its own sessions run, `contains` for "is this cwd ours", `other_dirs` for the `--add-dir`s, `owners` for which workspace supervises a folder; never a root of your own.
- `supraman_core::schedule`: a workspace's schedules at `<home>/schedules/<ws>.toml` (`load`, `edit` under its lock; a covered edit sets `pending`, never the approval), the covered `fingerprint` with `approve` (the app's Approve only, C100) and `verify_approval`/`effective_status`, `next_fire`/`previous_fire` in a given zone across DST, the run records (`append_run`, `runs`), a run's files (`live_dir` with the `Live` file, `state_dir`, `fire_log`), a schedule secret's `secret_key` and `masked_tail` for every recorded stderr, `SCHED_SLUG_PREFIX`, and a run's `session_name`/`run_id`/`run_worktree`/`run_branch`, `preamble`, `base_prompt` (slash command via `command_file`) and profile flags (`Profile::permission_mode`, `Permissions::allowed`/`denied`, `DEFAULT_DENY`); `prune::prune` covers its files.
- `supraman_core::schedule::{covered_diff, covered_fields, schedule_of_session}` and `Display for Trigger`: what Approve shows (the covered fields, or their change since `approval.covered`), a run session's schedule id from its name, and a trigger as `sm schedule add --every` takes it.
- `supraman_core::desktop::{HiddenDesktop, spawn_on, quote_arg, input_desktop_name, thread_desktop_name}`: a private desktop that is never switched to and a child started on it with its pipes back (the selftests' default, `supraman-app` `selftest_desktop`); never `SwitchDesktop`, never `SendInput`.
- `supraman_core::process::spawn_detached`: a child that outlives the call (Run now's `smw`), no pipes, no wait.
- `sm::fire::recover_if_dead`: a live file whose sm is gone, recovered as `interrupted` (stop, never rm; revoke) while no fire holds the lock; the app calls it each poll.
- `work_view::cards` and `view/left/inbox_card.rs` (supraman-app): the Inbox's Workman cards, read per project the workspace's folders bind (`WorkInbox`, `projects::bound`, never a project by name); Needs you brings the Inbox to its top, highlighted (`WorkInbox::show`): `cards::sections` sorts the rows into Needs you and Housekeeping's (kind, run) groups and says each card's text (`Card::texts`, never the resolving call), `inbox_card::render` paints one with its hover Open, Web, Copy and ×.
- `view/folder_list.rs` (supraman-app): a workspace's folder list (`FolderList` of `FolderRow`s: the folder, a tick only on a parent's subfolder or a Rescan's offer, home, `supervised in <ws>` from `owners`; `render` with [home], × and the add row of a path field, Browse and Add); the one list of the workspace dialog.

## Keep each concern in one place

**This binds every agent and subagent working in this repo — brief subagents on it when you delegate.** Workman rule C144; the two refactor passes (m5/44, refactor2) found these same mistakes twice, and they came back within a day.

1. **A second copy means extract.** A helper whose job already exists (format, hex, path, env, parse, open, validate) is the shared one, or the diff moves both into the owning crate.
2. **One lifecycle, one module.** Mint, revoke, launch, stop and persist of a session or token live in one owner; a new caller calls it, never copies its match arms.
3. **One reader per state file and env var**, inside its owner (`Registry::edit`, `Settings`, `paths::*`, …); no new `std::env::var` or read of a named state file elsewhere.
4. **Nothing blocking in a UI handler.** No `fs`, `Settings::load`, `lock_file`, process, `Client` or peer call inside a click, listener, render or poll handler: run it in the background, then apply the result.
5. **A persisted read-modify-write** holds `lock_file`, writes with `write_atomic`, and a failed load is a notice, never a default saved back.
6. **Size caps.** No new production fn over 80 lines; no file over 1,500 non-test lines grows (move something out first); new feature state goes on its own entity, not a `FleetView` field.
7. **The cheapest test that fails.** A new selftest step says why a unit test cannot do it; no fixed sleep, no hand-rolled server (`FakeWorkman`).
8. **Nothing open without a ref.** "Narrowed", "kept" or "deferred" in a report names a Workman item; a compat shim names the release that removes it.

A unit that breaks a clause says which and why in its report. The controller checks the diff against each clause before it merges.

## Comments state the present, not the past

**This binds every agent and subagent working in this repo — brief subagents on it explicitly when you delegate, because they default to narrating their own fix.** The full procedure is the `rlarch:code-comments` skill.

Comments are written subtractively. The default verdict on any comment — one you are about to write, one you find, one a subagent hands you — is **delete**. If you catch yourself weighing whether a comment earns its place, that deliberation is the answer.

A comment survives only when it says something the code cannot say by itself, in the **present tense**:

- No "used to", "previously", no naming a retired construct, no narrating what a change did.
- No teaching the reader what a language or framework feature does — the reader already knows Rust and gpui.
- No paraphrasing a rule decided in another file. Point at where the contract lives (`// replace covers a live token; see doc 14 §2.`) instead of restating it — the restatement goes stale and then misleads.
- Survivors get **one line**; more only when genuinely irreducible.
- Never *add* `///` docs during a cleanup pass. Doc comments on the shared components listed above stay.

Treat existing comments as untrusted: a comment that contradicts its code is wrong and gets deleted, not corrected — unless the contradiction suggests the *code* is the broken half, in which case report it and leave the code alone.
